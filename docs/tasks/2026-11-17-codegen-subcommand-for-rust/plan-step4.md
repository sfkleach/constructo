# Plan: step 4 of codegen, the Rust types

This plans step 4 of the [implementation plan](implementation-plan.md): the command `constructo codegen --lang=rust`,
which writes the Rust types of a run from the model of step 3. There is no codec yet, so the file is types only, and
it compiles with no crate at all. Step 5 adds the codec to the same file.

## What the code has today

- **The model,** `constructo::build_model`, in `src/codegen/model.rs`: the projects, the enums with their constructors
  and the form in which the root writes each, the record types without a name with the projects that use each, the
  consts, `boxed` on every field and parameter, `has_default` on every enum, and `TypeRef::can_be_absent`. It has no
  positions: nothing in it says where a declaration is written.
- **The command line,** `src/main.rs`: `check`, `convert`, `query` and the project commands. The typed inputs are
  `TypingArgs`, which `convert` and `query` flatten: `--project`, `--dev`, `--prelude`, `--widening`, `--allow-refs`,
  `--infer-limit` and `--default-limit`. `ProjectSet::layout` divides the sources among the projects.
- **Warnings:** `Diagnostic::warning(file, pos, message)` prints as `WARNING: message (file, line L, col C)`, and
  `convert` already gives one, for the values that it leaves out.
- **Identifiers** are ASCII: a type or constructor starts with a capital letter, and a field, a const or a record name
  made from fields starts with a lower-case letter or `_`. A type parameter is a type name.
- **No file is written in place** by any command yet. `fetch` moves a finished folder into place with a rename.

## The command

```
constructo codegen --lang=rust [--project=FOLDER] [--out-file=FILE_PATH] [TYPING OPTIONS] [FILES]...
```

- **`--lang`** is required, and `rust` is its one value, matched exactly. Another is a usage error that lists the
  values: `Unknown language python: the languages are rust`.
- **The inputs** are those of `convert --to=json-typed`: `TypingArgs`, the experimental options, `--stdin`, and the
  files, which are types files and values files. `--project` or a file is required.
- **The output** goes to `--out-file`, or to the standard output. A file is written to a new file beside it, which then
  takes the place of the old one by a rename, so that a run that fails leaves the old file as it was. `--out-dir` is a
  usage error, `Rust writes one file: use --out-file=FILE_PATH, or neither for the standard output`, and both together
  are one too. `--adopt` is added in step 6.
- **Exit codes** as for `check`: 0, 1 when the inputs have errors, which are reported as `check` reports them and stop
  anything from being written, and 2 for a usage error or a file that cannot be read or written.
- **Renamings are warnings** on the standard error, with exit code 0 (below).
- **The library** has `codegen::rust::generate(&Model) -> Generated`, with the text and the warnings, so that it is
  tested without the command line, and the command only builds the model, calls it and writes the result.

## What the file holds

A header, `//! Generated by constructo codegen from the project NAME. Do not edit.`, or `from types files` without a
project, then `#![allow(non_camel_case_types, non_snake_case, dead_code)]`, then the root project's items, then one
`pub mod` for each other project, in the order of the layout. The prelude has no module, since its `Bool` and `Option`
are Rust's own, and nor does any other built-in project. A project with no types has an empty module, so that the
paths to it never depend on what it declares. Nothing in the file depends on the time, the paths of the inputs or the
version of `constructo`, so that it changes only when the declarations do.

Each item has a doc comment with the Constructo full name, such as ``/// `com.example.shapes::Circle` ``, so that a
renamed one can be found, and every item and field is `pub`. Every type derives `Debug`, `Clone` and `PartialEq`, and
not `Eq`, `Hash` or `Copy`, which a `Float` field or a later field would take away, a change that would break a
program for a change to the declarations that means nothing to it.

The mapping is the draft's table:

- **An enum of several constructors** is a Rust `enum` with a variant for each, in order. A constructor with no body is
  a variant with no data, and any other is a tuple variant that holds the `struct` of the constructor:
  `Circle(Circle)`. The variant has the Constructo name, even where the `struct` is renamed.
- **An enum of one constructor** is one `struct`, named after the enum, with the body of the constructor:
  `struct Point { pub x: f64, pub y: f64 }`, `struct Temperature(pub f64)`, or `struct Unit;`.
- **The body of a constructor:** a tuple with no names is a tuple `struct`, `Ping()` included; a tuple with names is a
  `struct` with named fields, where a parameter with no name is `_0`, `_1` and so on by its position; a record is a
  `struct` with named fields in the order of the declaration; an array is a tuple `struct` of a `Vec`.
- **The parameters** of an enum are its own, and those of a constructor's `struct` are the ones that occur in its body,
  in the enum's order, as the draft says. A record without a name has the model's `A`, `B` and so on.
- **The types:** `Nat`, `Int` and `Float` are `u64`, `i64` and `f64`, `String` is `String`, `[T]` is `Vec<T>`, the
  prelude's `Bool` is `bool` and its `Option<T>` is `Option<T>`, and a parameter is itself.
- **A boxed field** is `Box<T>`, and a boxed `Option<T>` is `Option<Box<T>>`, as the draft's `next: Node?` is, with the
  rule applied again to `T`. An array is never boxed.
- **Records without a name** are written in the module of each project that uses them, as the draft says, with the
  model's name.

**Every path is written in full,** so that no name of the user's can hide one that the file needs:

- the std items, as `::std::vec::Vec`, `::std::boxed::Box`, `::std::option::Option` and `::std::string::String`;
- the primitive types, as `::std::primitive::u64`, `::std::primitive::f64` and `::std::primitive::bool`, since a
  record whose one field is `u64` is a `struct u64` that would otherwise hide the primitive in its module;
- a generated type, as `self::Shape` in its own module and `super::Shape` or `super::com_example_ids::Uuid` from a
  submodule. A type parameter is the only name written bare. **Decided,** since it settles a clash that the draft does
  not mention: the record of `{ x: T, y: Point }` in `Foo<T>` is `x_y<A>`, and an enum `A` of the project would be
  hidden by the parameter `A` if it were written bare. `self::A` is the enum whatever the parameters are.

## Names

The draft's section "Modules and names in Rust" is implemented as it is:

- **Modules:** the parts of a project's name joined with `_`, with the case kept. A clash between two projects, or
  between a project and a record of the root, is settled by number, `_2` and so on, in the order of the layout, the
  record keeping its name.
- **Keywords:** a field, a parameter or a type that is a keyword of Rust 2021 or a reserved word, `gen` of Rust 2024
  among them, is a raw identifier, `r#type`. `self`, `super`, `crate`, `Self` and `_` cannot be raw and get a `_` at
  the end, repeated while that is the name of another field of the same `struct`, as is a named parameter that clashes
  with a position's `_0`.
- **A constructor called like an enum** of its module is `ShapeCircle`, and a number after that is the last resort.
- **The fixed names**, `Codec`, `codec`, `ReadValue`, `WriteValue` and `DefaultValue`, are reserved from this step on,
  though step 5 writes them, so that the names of a program's types do not change when the codec arrives: a type of
  the user's called `Codec` is `Codec_`.
- **Every renaming is a warning,** with the Constructo name and the Rust name, and why:
  `WARNING: The constructor com.example.shapes::Circle is ShapeCircle in Rust, since the enum Circle has its name`.
  A raw identifier is not a renaming, since `r#type` is the same name to Rust, and gives no warning.

## Decided

**A type parameter that no field holds.** `enum Phantom<_T> = Phantom;` is valid, since a parameter that starts with
`_` may be unused (decision 3), but Rust refuses a type parameter that no field uses (E0392). The outline expected a
`PhantomData`. **Decided** instead: **such a parameter is left out of the Rust type,** and out of every use of it, so
`Phantom<Nat>` is `Phantom`. A parameter is kept if a field holds it, directly or as the argument of a kept parameter
of another type, worked out as a fixed point, as the model works out what is held. Nothing is lost, since no value
differs by it, and the type has nothing that the declaration does not, which is what the draft's open question was
worried about. The cost is that the Rust type has fewer parameters than the Constructo one, which an adoption in step 6
has to follow. A `PhantomData` field instead would be in every value that a program builds, and for an enum of several
constructors needs a hidden variant, which every `match` would have to name.

**Where a warning points.** The model has no positions, so a warning could only name the declaration. **Decided:** the
model gains the file and position of each enum, constructor, field and parameter, and a warning is at the declaration,
as every other message of `constructo` is at the place it is about.

## The tests

- **Unit tests** of `codegen::rust`, on the text for small declarations: each body, one constructor, generics, a
  parameter left out, boxing with and without an `Option`, records in two modules, and each rule of names with its
  warning.
- **A functest that compiles:** for every valid types example and project example, generate the file, and compile it
  with `rustc --edition=2021 --crate-type=lib`, in `_build/`, with `-D warnings` so that a lint that the header does
  not allow is found. The same for a types file of hard names, `syntax/examples/codegen/names.types`: keywords, the
  field `_`, types called `Vec`, `Box`, `Option`, `String`, `Result` and `u64`, an enum called `Codec`, a constructor
  called like an enum, and the clashes of modules.
- **The scenario:** the two projects of `scenario-shapes/projects` are copied to `syntax/examples/codegen/shapes/`,
  since the task folder moves, and the output for them is checked in as `syntax/examples/codegen/shapes.rs`. A
  functest compares the two, so that a change to the generated code is seen in review. It has no adoptions until step
  6.
- **The command:** `--lang` unknown or missing, `--out-dir`, both outputs, an error in the inputs writes nothing and
  leaves an old `--out-file` as it was, and the warnings with exit code 0.

## Decisions

- **0049: how the modules and names in Rust are chosen**, with the names that the generator adds and why a Constructo
  name yields to them: the draft's section, the paths written in full, and the parameters left out.
- **0050: a target writes one file or a folder**, with `--out-file` and `--out-dir`, the wrong one an error that names
  the right one, and the file or folder replaced at once. Rust writes only the first; the folder is written down now,
  as the outline puts it here, so that Python does not decide it again.

## As it was built

*Done,* in the four commits above. What the plan did not say:

- **A type that holds itself with other arguments is refused.** Compiling the output found that Rust's drop-check
  overflows on `Nested<T> = Flat(T), Deep(Nested<[T]>)` as soon as a value is made, through a `Box` or a `Vec`, so
  `generate` returns an error at the declaration, and `syntax/examples/codegen/refused/` has the case. The check is in
  `src/codegen/rust/regular.rs`, and Tarjan's algorithm moved to `src/codegen/graph.rs` for it.
- A constructor that has the name of its own enum takes the prefix too, as `HolderHolder`.
- A parameter that is left out is a warning, unless its name starts with `_`.
- The prelude has a module if it declares anything besides `Bool` and `Option`, which it does not today.
- The model's projects have the indexes of their files, so that a module that is renamed is reported at the start of
  its first types file. One with no types files is reported with the name of the project.
- The warnings are given in the order of the files and of the places in them.
- The examples are `names.types`, `shapes/` with `shapes.rs`, and `refused/`, and the compiled output is kept in
  `_build/functest-codegen`.
